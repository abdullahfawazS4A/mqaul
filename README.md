# موقع محاسبة مقاولات — Frontend فقط

تطبيق React (Vite) + Tailwind CSS لمحاسبة أعمال المقاولات، بواجهة عربية RTL بالكامل.
**لا يوجد Backend ولا قاعدة بيانات** — كل البيانات في ذاكرة التطبيق (React state) وتعود لحالتها الأولية عند تحديث الصفحة.

## التشغيل

```bash
npm install
npm run dev      # خادم التطوير
npm run build    # بناء للإنتاج
npm run preview  # معاينة البناء
```

## الأقسام

| المسار | الواجهة | الوصف |
| --- | --- | --- |
| `/treasury` | الصيرفة | إيداع/استلام من الصندوق، والرصيد يُحسب تلقائيًا |
| `/debts` | الديون | رأس المال، الأشخاص، إضافة دين وسند قبض، سجل حركات لكل شخص |
| `/lists` | القوائم | سجل شكلي للقوائم (قيمة/ربح/حالة) بلا أي أثر حسابي |
| `/projects` | المشاريع | قائمة المشاريع |
| `/projects/:id` | تفاصيل المشروع | إيداعات الشركاء، المصاريف، السلف المستلمة + ملخص |

## ربط Backend لاحقًا

كل الوصول للبيانات يمر عبر `src/data/DataContext.jsx` — لا يستورد أي مكوّن واجهة بيانات مباشرة.
للانتقال إلى API حقيقي:

1. استبدل جسم الدوال داخل `DataContext.jsx` (مثل `addTreasuryEntry`, `addDebt`, `addProjectItem`) بنداءات `fetch`/`axios` مع الإبقاء على نفس التواقيع والقيم المُعادة.
2. استبدل `useState(seed…)` بجلب البيانات (`useEffect` أو React Query) واحذف `mockData.js`.
3. الدوال التي تُرجع `{ ok, error }` (`addDebt`, `addReceipt`) تُبقي نفس الشكل حتى تستمر رسائل الخطأ بالظهور داخل النماذج كما هي.

المكوّنات و`hooks` لن تحتاج أي تعديل.

## قواعد العمل المطبّقة

- **الصيرفة:** الرصيد = مجموع الإيداعات − مجموع الاستلامات، والعمليات مرتّبة من الأحدث للأقدم.
- **الديون:** الرصيد الكلي المتاح = رأس المال − الديون القائمة.
  إضافة دين بمبلغ أكبر من الرصيد المتاح **مرفوضة** مع رسالة خطأ واضحة، وسند القبض لا يتجاوز دين الشخص ويعيد المبلغ للرصيد المتاح.
- **القوائم:** أرقام للعرض فقط — لا تؤثر على الصيرفة أو الديون إطلاقًا.
- **المشاريع:** الملخص يعرض مجاميع الإيداعات والمصاريف والسلف لكل مشروع على حدة.
